# 云台 yaw / pitch 轴故障排查记录

- 日期：2026-11-01
- 平台：Jetson Nano（L4T / Ubuntu 20.04）
- 总线：`can0`，CANable2 + `slcand`，1 Mbps
- 挂载节点：STM32F407 底盘（11-bit 标准帧 `0x110~0x114`）+ ZDT Emm42 闭环步进（29-bit 扩展帧，ID = `addr<<8 | packet`）
- 云台参数：**yaw 传动比 2:1、pitch 直连 1:1**；细分 16 → 3200 脉冲/电机圈
- 换算关系：`电机 RPM = 输出角速度(°/s) × 传动比 ÷ 6`（yaw：360°/s ↔ 60 RPM；pitch：120°/s ↔ 20 RPM）
- 状态位（ZDT `0x3A` 回帧）：bit0 使能 / bit1 到位 / bit2 堵转 / bit3 堵转保护

## 1. 初始故障现象

1. 上下方向键控制的是 **yaw（水平）轴**，左右方向键无反应；
2. yaw 轴电机"好像只能顺时针一个方向转"；
3. 按一次之后彻底不动，左右都无效。

最终确认这是**四层独立问题叠加**，逐一排查如下。

## 2. 问题一：yaw / pitch 电机地址互换（软件）

### 现象与证据

- 配置里 `yaw_addr = 2`、`pitch_addr = 1`，而实机接线的 **yaw 电机在 ID 1、pitch 在 ID 2**。
- 于是：`←/→`（yaw 命令）发往 ID 2 → 该节点不在总线上 → 毫无反应；`↑/↓`（pitch 命令）发往 ID 1 → 正好驱动了物理上的 yaw 电机。
- 总线取证：

| 地址 | CAN ID | 请求 | 回帧 | 判定 |
|---|---|---|---|---|
| 1 | `0x100` | `35 6B` / `36 6B` / `3A 6B` | `35 00 00 00 6B` / `36 01 00 00 00 09 6B` / `3A 03 6B` | 电机在线 |
| 2 | `0x200` | 同上 | **无任何回帧** | 节点不存在（pitch 尚未接入） |

### "只能单向转"的解释

命令走的是 pitch 轴的配置，而 pitch 有 `±45°` 软限位（`axis.cpp` 的 `clampToLimits()` + 角度硬夹带 5° 余量）。yaw 电机被当作 pitch 驱动后，转到 +45° 即被钳成 0 输出，表现为"转一下就卡住/回不来"。yaw 轴本身是 `use_soft_limits=false`（导电滑环 360° 无机械限位），这个限位本不该套在它身上。

### 处理

修改 `src/main.cpp` 共 4 处：`Options` 两行默认值（`yaw_addr=1`、`pitch_addr=2`）、`--yaw-addr/--pitch-addr` 缺参兜底值、usage 文案、文件头注释。
原文件备份为 `src/main.cpp.bak-20261101`（该目录无 git 版本管理）。

客户端 `~/gimbal_ctl` 无需改动：其按键映射原本就是 `←/→ = yaw`、`↑/↓ = pitch`。

## 3. 问题二：堵转保护锁死，且软件解除命令无效（协议）

### 现象与证据

电机转一下就完全停止响应速度命令。状态回帧由正常的 `3A 03`（使能+到位）变为：

```
3A 0D   →  bit0=1 使能   bit2=1 堵转   bit3=1 堵转保护
```

### 关键发现

驱动板确实支持解除保护（功能码 `0x0E`），但工程的 `mkClearStall()` 只发出 `[addr, 0E, 6B]`，驱动板回 `0E EE 6B`（命令不成立），**软件侧永远解不开保护**。

正确的解除帧需要带上固定数据字节 `0x52`：

| 发送 | 回帧 | 含义 |
|---|---|---|
| `0E 6B` | `00 EE 6B` | 命令不成立（帧长度/数据缺失） |
| `0E 52 6B` | `0E 02 6B` | 动作完成，保护解除 |

解除后状态位立即回到 `3A 03`。

## 4. 问题三：杜邦线供电内阻过大（供电）

### 测量方法

以驱动板 `0x24`（读母线电压）为准，边驱动边采样：空载 1.2 s → 带载 2.0 s（指令 10 RPM = 30°/s，acc=200）→ 停转 0.8 s。

### 对照数据（同一脚本、同一指令）

| 供电方式 | 空载母线平均 | 带载母线最低 | 跌落 | 带载实测转速 |
|---|---|---|---|---|
| 杜邦线 | 11874 mV | **9140 mV** | **2734 mV（23.0%）** | **0 RPM（转不动，直接进堵转）** |
| 18AWG | 12366 mV | 11405 mV | 961 mV（7.8%） | 8 RPM |

按驱动电流 1.5~2 A 反推，杜邦线回路总电阻约 **1.4~1.8 Ω**，对步进驱动不可接受：电压先塌，力矩随之塌陷，表现为"能起步但立刻堵转"。

### 结论

换 18AWG（正负两根都要换、尽量短）后跌落从 23% 降到 7.8%，电机由"完全转不动"变为"能转"。后续在问题四解决后，同样 18AWG 供电下带载满速 40 RPM 时压降仅约 170 mV。

## 5. 问题四：装配过紧导致负载超过电机输出力矩（机械）

### 空载 / 带载对照（同一套电机与供电）

空载（电机脱离负载）：

| 指令 | 实测 | 母线 | 状态 |
|---|---|---|---|
| 5 RPM (15°/s) | 5 | 12269 mV | 正常 |
| 10 RPM (30°/s) | 10 | 12269 mV | 正常 |
| 20 RPM (60°/s) | 20 | 12249 mV | 正常 |
| 30 RPM (90°/s) | 30 | 12246 mV | 正常 |
| 40 RPM (120°/s) | 40 | 12246 mV | 正常 |

压降仅 120 mV，每一级都精确跟随，证明**电机、驱动板、相线、电流设置、供电、总线全部健康**。

带载（同一时刻）：

| 试验 | 实际转角 | 实测转速 | 状态 |
|---|---|---|---|
| dir=1 @3 RPM，1.5 s | **+3 脉冲**（理论 +29491） | 5 RPM（瞬时抖动） | 0x05 堵转 |
| dir=0 @3 RPM，1.5 s | **0** | 0 RPM | 0x0D 保护立即触发 |
| dir=1 再试 | **0** | 0 RPM | 0x07 堵转 |

### 判据

"空载 40 RPM 正常 + 带载 3 RPM 就堵 + 手转不卡"三条同时成立，排除缺相与电流档位问题（缺相会在空载也表现无力矩），指向**负载侧阻力超过电机输出力矩**。该现象出现在一次机械拆装之后，属于装配压紧/同轴度问题。

### 处理

重新装配负载后，同一套参数下带载表现：

| 指令 | CCW 实测 | CW 实测 | 母线 | 状态 |
|---|---|---|---|---|
| 3 RPM (9°/s) | 3 | — | 12222 mV | 正常 |
| 5 RPM (15°/s) | 5 | 5 | 12222 / 12240 mV | 正常 |
| 8 RPM (24°/s) | 8 | — | 12222 mV | 正常 |
| 12 RPM (36°/s) | 12 | — | 12222 mV | 正常 |
| 16 RPM (48°/s) | 17 | — | 12202 mV | 正常 |
| 20 RPM (60°/s) | 20 | 21 | 12199 / 12200 mV | 正常 |
| 30 RPM (90°/s) | 31 | — | 12199 mV | 正常 |
| 40 RPM (120°/s) | 40 | 41 | 12191 / 12193 mV | 正常 |

带载压降 12366 → 12191，约 **175 mV**（空载为 120 mV），负载已不再构成额外阻力。

## 6. 最终端到端验证

经 UDP `40001` 下发控制帧（客户端协议 → daemon → CAN → 电机），每段持续 2.0 s：

| 指令 | 遥测输出角速度 | 电机实测（0.01 RPM 单位换算后） | 状态位 |
|---|---|---|---|
| +120°/s | +120.00°/s | 40.00 RPM | 0x03 ✅ |
| −120°/s | −120.00°/s | 41.00 RPM | 0x03 ✅ |
| +60°/s | +60.00°/s | 20.00 RPM | 0x03 ✅ |
| −60°/s | −60.00°/s | 21.00 RPM | 0x03 ✅ |

全程 `0x40`（堵转）位一次未出现；`0x0B` 为操作端停手后看门狗置位（`0x08`），属正常行为。

> 数据注记：上表角度积分为**指令符号的反向**（指令 +120°/s 时遥测转角约 −212.9°，指令 −120°/s 时约 +215.4°），即转速反馈与下发命令的符号约定不一致。yaw 轴无限位，暂不影响使用；但 pitch 软限位依赖角度符号判定，接入 pitch 前需一并核对。

## 7. 排查过程中另外踩到的两个坑

1. **多个 `slcand` 抢占同名 `can0`**：反复插拔 CANable2 导致 `ttyACM0/1/2` 三份 `slcand` 同时存在，`can0` 名称被反复改名/抢占，最后存活的那个绑定在已消失的设备上，表现为 `RX: 0 packets`（接收路径死）且 daemon 报 `[chassis-can] 连接丢失 (read: No such device)`。清理全部 `slcand` 并用 `by-id` 固定设备路径重建单个实例后恢复。
2. **`pkill -f slcand` 会匹配到执行该命令的 ssh 会话自身**，把操作自己的 shell 一并杀掉。按名字匹配时应使用 `-x`，或用 `"slcan[d]"` 这类括号写法避免自匹配。

## 8. 结论

| 层 | 问题 | 处理 |
|---|---|---|
| 软件 | `yaw_addr` / `pitch_addr` 默认值互换 | 改为 yaw=1、pitch=2 |
| 协议 | `mkClearStall()` 缺固定数据字节 `0x52`，软件无法解除堵转保护 | 确认正确帧为 `0E 52 6B` |
| 供电 | 杜邦线内阻过大，带载压降 23% | 改 18AWG，压降至 7.8% 以下 |
| 机械 | 装配过紧/偏心导致负载超力矩 | 重新装配后带载满速 120°/s 正常 |

四层问题叠加时，表面症状都是"按方向键没反应"，但根因彼此独立，必须逐层用总线回帧、母线电压、位置回读三类客观数据区分，不能只看现象。

# 第二阶段：pitch 轴接入与角度/限位改造

> 接上文。第一阶段解决了 yaw 侧的地址、堵转、供电、装配四个问题；本阶段处理 **pitch 电机接入总线后暴露出的角度与限位问题**，最终把两轴参数分开配置并对软限位做了可信化改造。

## 9. 两轴参数不再共用

### 9.1 pitch 是直连，没有减速比

机构确认：**pitch 直接连接发射机构，无减速**（yaw 是 2:1 减速）。而原代码两轴共用同一个 `--gear`：

```cpp
gc.yaw.gear_ratio   = o.gear;        // 2.0  正确
gc.pitch.gear_ratio = o.gear;        // 2.0  错误：实际 1:1
```

错误传动比会造成两个后果，第二个是安全隐患：

| 影响 | 2.0 被误用到 1:1 轴上 |
|---|---|
| 下发转速 | `rate × 2 / 6`，电机被要求跑 2 倍速度 |
| 角度估计 | `rpm × 6 / 2`，估计角只有真实的一半 |
| **软限位** | 触发时真实角度已到设定值的 2 倍 → **限位形同虚设** |

处理：新增 `--pitch-gear`（默认 **1.0**），pitch 走自己的传动比，`--gear` 仍只用于 yaw。

### 9.2 最终参数表

| 轴 | 地址 | 传动比 | 软限位 | 最大角速度 |
|---|---|---|---|---|
| yaw | 1 | 2.0（减速） | 无（导电滑环 360°） | 180 °/s |
| pitch | 2 | **1.0（直连）** | **±30°**（上抬 30 / 下压 30） | 120 °/s |

对应 CLI：`--yaw-addr 1 --pitch-addr 2 --gear 2.0 --pitch-gear 1.0 --pitch-limit -30 30`

> pitch 软限位经历过 45 → 60 → 50 → 40 → **30** 的调整：
> 曾一度配置为不对称的「上 40 / 下 30」，最终按机构实际安全行程统一为 **±30**。

## 10. 转速反馈符号错误（与下发命令相反）

### 现象

命令正方向输出，遥测的角速度为正，但角度积分却在往负方向走：

| 指令 | 遥测 act | 电机实测 | 角度变化 |
|---|---|---|---|
| +120 °/s | +120.00 | 40 RPM | **−212.9°**（理论 +240） |
| −120 °/s | −120.00 | 41 RPM | **+215.4°** |

### 根因

下发与反馈两条路径的符号约定相反，且 `invert_dir` 无法修正（它把两边一起翻，相对关系不变）：

```cpp
// 命令路径：正速度 -> dir 字节 = 0x01
const bool ccw = (positive != cfg_.invert_dir);

// 反馈路径（改前）：dir 字节 = 0x01 -> 判成【负】转速
st_.speed_rpm = (f.data[0] != 0) ? -rpm : rpm;
```

对 yaw 只是显示反向（无限位，无害）；**对 pitch 是危险的**：软限位依赖角度符号，符号反了会"命令往上、却被下限位掐死"。

### 处理与验证

反馈改为 `dir=1 → 正`。修复后四者同向：

| 试验（各 1 s，±9 °/s） | 指令 | 遥测 act | 角度变化 |
|---|---|---|---|
| pitch +9 | +9.0 | +9.00 | +6.47° |
| pitch −9 | −9.0 | −9.00 | −6.68° |
| yaw +9 | +9.0 | +9.00 | +7.26° |
| yaw −9 | −9.0 | −9.00 | −6.39° |

## 11. 角度跟踪改用位置反馈（软限位可信化的关键）

### 问题

改完符号后仍发现：**估计角只反映真实转角的约 56%**。

| 3 秒内 | 变化量 |
|---|---|
| 真实位置（`candump` 观测 `0x36`） | +4469 脉冲 = **24.56°** |
| daemon 估计角 | **+13.69°** |

估计角原本靠**转速积分**（`est_angle += rpm × 6 / gear × dt`），在同一批测试中还有过"估计角爬到 +60 而被限位掐死、但真实位置根本还没到"的现象，表现就是按方向键**完全不动**。

### 改造

`0x36`（实时位置）已由 `ZdtMotor` 每 100 ms 轮询，但只用于显示。改为：

1. `ZdtMotor` 内把 16-bit 位置（`dir` 字节 + 0~65535）**累积成连续角度**，跨圈按 ±32768 解绕；
2. 提供 `hasPosFeedback()` / `posDegSigned()` / `resetPosAccum()`；
3. `Axis::update` **优先用位置反馈**算 `est_angle_`，只有拿不到位置帧时才退回转速积分（兜底，会漂）。

```
if (motor_->hasPosFeedback()) est_angle_ = motor_->posDegSigned() / gear;
else                          est_angle_ += (rpm × 6 / gear) × dt;   // 兜底
```

同时把 `0x36` 的方向符号也统一为 `dir=1 → 正`，与速度反馈一致。

### 验证

归零后往上转：估计角 +50.44°，实测位置 +9183 脉冲 = **+50.44°** —— **1:1 精确，偏差 0.01°**。往返一圈回到原点误差 0.05°，无累积漂移。

## 12. 使用前提：每次启动必须归零

daemon 启动时把**当时的位置**作为 `0x36` 累积器的 0° 基准（`pos_ok_` 初始为 false，首个位置帧定基准）。因此：

> **每次启动 daemon 后，先把 pitch 摆到水平，按客户端 `z` 归零**；之后 ±30° 才对应真实的上下各 30°。

不归零的话限位基准是歪的（以启动瞬间的姿态为 0°）。

## 13. 排查中的干扰源与新坑

### 13.1 两个操作端同时发命令（最隐蔽）

`F6` 命令帧在 `2 RPM` 与 `0` 之间反复横跳，电机表现为"动一下就停"。daemon 日志暴露了原因：

```
[ctrl] 操作端: 127.0.0.1:49748      <- 测试脚本
[ctrl] 操作端: 192.168.2.1:35102    <- 运行中的 gimbal_ctl 客户端
```

PC 客户端以 100 Hz 发 `0`，测试脚本以 100 Hz 发 `-12`，`setRate` 每包调用一次，最终表现为交替命令。**做任何测量前必须确认只有一个操作端**。

### 13.2 编译被时钟回退悄悄跳过

Jetson 无 RTC，重启后时钟回退。源码 mtime（`2026-11-01 21:26`）比 `.o`（`2026-11-03 01:02`）**旧**，`make` 判定目标已最新、**直接跳过重编**，二进制里根本没有新参数（`--help` 查不到 `--pitch-gear`）。

判据：改完代码先 `--help` 确认新参数存在；异常时 `cmake --build build --target clean` 后全量重编。

### 13.3 多个 `slcand` 抢同名 `can0`

反复插拔 CANable2 会留下 `ttyACM0/1/2` 多份 `slcand`，`can0` 名字被抢占，最终存活的那个绑定在已消失的设备上 → `RX: 0 packets`、daemon 报 `read: No such device`。清理后**用 `by-id` 固定路径**只建一个实例：

```bash
sudo pkill -x slcand && sudo ip link del can0 2>/dev/null
sudo slcand -o -s8 /dev/serial/by-id/usb-Openlight_Labs_CANable2_..._209730595330-if00 can0
sudo ip link set can0 up
```

### 13.4 装电池后总线零流量 —— 属物理接线问题

装电池并整理线束后，`can0` 接口正常 UP，但出现**双向彻底零流量**：

```
RX: 0 packets / 0 bytes
TX: 0 packets / 0 bytes      ← 连自己发的查询帧也没计数
3 秒抓包：0 帧（正常应有底盘 0x110~0x114 共 500 帧/s）
ZDT 地址扫描 addr 1/2：无应答
```

判据：**接口 UP 但零流量 = 物理层问题**（CAN_H/CAN_L 被碰掉、驱动板或 STM32 掉电），不是软件/协议问题。查线复产即可。

## 14. 电池负载下的保持能力实测

发射机构需挂电池，担心负载加重后 pitch 压不住。测试流程固定：**归零 → 抬到十几度 → 松手静止 15 秒**，看漂移、温度、堵转位。

| 指标 | 空载基线 | 带载（电池已装） |
|---|---|---|
| 抬升角度 | +13.73° | +18.84° |
| 15 s 静置漂移 | **0.000°（0 脉冲）** | **0.240°（43 脉冲）** |
| 温度 | 30 ℃ | 28~29 ℃ |
| 堵转位 | 无 | 无 |
| 母线 | — | 12082 → 12036 mV |

带载全程行程（8 °/s ≈ 2.7 RPM；**本节采集时限位为 ±40°，后调整为 ±30°**，行程余量结论不变）：

| 动作 | 结果 |
|---|---|
| 上行 | 停在 **+40.02°**，限位触发，实测位置变化 +39.93° |
| 下行 | 停在 **−40.57°**，限位触发 |
| 全程 | **无堵转、无丢步** |
| 回中 | 回到 +1.39°（收尾步进误差，非丢步） |

结论：**直连 + 电池负载下，保持与全程行程均正常**，无需改结构或提高驱动电流。
